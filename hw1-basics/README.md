# ДЗ1 - «Утечка данных»

## Сюжет

Вы - junior-аналитик. ИИ-ассистент должен был подготовить маркетинговый
отчёт, но что-то пошло не так: часть данных зашифрована, часть перепутана,
часть просто «грязная». Доверять результату вслепую нельзя и теперь его нужно
восстановить вручную, шаг за шагом.

Задания связаны сюжетно: чтобы двигаться дальше по истории, нужно сначала
разобраться с текущим шагом. Технически каждое задание проверяется
отдельно, но полезно проходить их по порядку.

## Формат

Четыре задания - `task1.py`, `task2.py`, `task3.py`, `task4.py`. В каждом
файле есть одна функция с готовой сигнатурой и докстрингом - её нужно
реализовать вместо `...`. Менять сигнатуру функции (имя, аргументы) нельзя -
по ней вас проверяет автотестирование.

В каждом файле внизу есть блок `if __name__ == "__main__":` - он уже
написан, трогать его не нужно. Он подгружает пример данных из `data/` и
печатает результат, чтобы вы могли проверить себя локально:

```bash
python task1.py
```

Данные в `data/` - это **примеры** для отладки, а не то, на чём вас будут
проверять. Реальная проверка идёт на скрытых тестах с другими входными
значениями (в том числе граничными случаями), которых вы заранее не видите.

## Как сдавать

Реализуйте функции в `task1.py`–`task4.py` (`task5.py` - опциональный бонус,
см. ниже), закоммитьте и запушьте - GitHub Actions прогонит проверку
автоматически. Ваш балл - это процент пройденных тестов, он выводится прямо
в summary запуска (открыть запуск в разделе Actions вашего репозитория -
процент показан над логами шагов, отдельной строкой для основного задания
и отдельной для бонуса).

Локально можно (и стоит) прогнать публичные тесты, которые лежат в
`public_tests/` - они проверяют самые очевидные случаи и помогают убедиться,
что функция вообще работает и не падает с ошибкой:

```bash
pip install -r requirements.txt
pytest public_tests/
```

**Важно:** публичные тесты - это только дымовая проверка на очевидных
случаях. Они не покрывают все ситуации, которые проверяет реальная система
оценки. Пройденные публичные тесты не гарантируют полный балл - подумайте
сами, какие граничные случаи может не учитывать ваше решение.

## Задание 1. Расшифровка

Файл `task1.py`, функция `decode_caesar_cipher(text, shift)`.

Отчёт зашифрован шифром Цезаря: каждая латинская буква сдвинута вперёд по
алфавиту на `shift` позиций. Вам нужно расшифровать текст - сдвинуть буквы
обратно. Регистр букв должен сохраняться. Все символы, кроме латинских букв
(цифры, пробелы, знаки препинания), в шифровке не менялись.

Пример: `decode_caesar_cipher("Khoor!", 3)` → `"Hello!"`.

## Задание 2. Парсинг лога

Файл `task2.py`, функция `filter_events_after(log_lines, user, after_time)`.

В расшифрованном отчёте сказано, когда началась подозрительная активность.
Нужно найти в логе (`data/task2_log.txt`) все события конкретного
пользователя, которые произошли строго позже заданного времени.

Формат строки лога: `"<время> <пользователь> <событие>"`, например
`"19:05 mktbot7 export"`. Время - часы:минуты, 24-часовой формат; часы могут
быть записаны без ведущего нуля.

## Задание 3. Агрегация

Файл `task3.py`, функция `analyze_activity(user_ids)`.

По списку ID пользователей, засветившихся в подозрительных событиях,
постройте: словарь счётчиков (сколько раз встретился каждый ID), количество
уникальных пользователей и ID пользователя с наибольшим числом действий.
Если максимум делят несколько пользователей - возвращается тот, кто раньше
всех встретился в списке.

## Задание 4. Валидация CTR

Файл `task4.py`, функция `average_ctr(records)`.

Последний шаг - посчитать средний CTR по рекламным объявлениям
(`data/task4_ads.csv`). Часть записей повреждена и должна быть исключена из
расчёта: подробности того, что считается «грязной» записью - в докстринге
функции.

## Критерии оценки

Каждое задание проверяется независимым набором скрытых тестов - вы не видите
ни сами тест-кейсы, ни ожидаемые значения. Итоговый балл - это доля
пройденных тестов. Частичное решение лучше,
чем отсутствие решения: если не получается одно задание, переходите к
следующему - они проверяются независимо.

## Задание со звёздочкой (трек «Смешарики»)

Если базовые 4 задания дались легко - файл `task5.py`, функция
`decode_vigenere_cipher(text, key)`: шифр Виженера, где сдвиг для каждой
буквы свой и определяется соответствующей буквой ключа `key` (ключ
циклически повторяется по буквам текста; подробности и ловушка - в
докстринге функции). Пример данных - `data/task5_encoded.txt`.

Это не входит в обязательный балл: в Actions результат task5 проверяется
отдельным шагом `Run bonus task (Vigenère cipher)`, который не блокирует
основную проверку, даже если бонус не сделан или не пройден.
