# ДЗ2 - «Утечка данных: восстановление»

## Сюжет

Отчёт из ДЗ1 расшифрован, но в бонусном задании про шифр Виженера
вскрылась вторая деталь: экспорт данных был подписан токеном ИИ-ассистента.
Вам передали код, которым этот ассистент генерировал отчёты по рекламным
кампаниям, - `messy_code.py`. Он работает, но написан плохо: всё в одной
функции, дублирование, зашитые баги. Прежде чем снова доверять этому отчёту,
его нужно привести в порядок.

## Формат

Запустите `python messy_code.py` и посмотрите, что идёт не так, - это не
задание, а иллюстрация проблемы. Дальше пять файлов с заданиями:
`task1.py`-`task4.py` (обязательные) и `task5.py` (бонус,
продвинутый трек). В каждом файле - одна или несколько функций с готовой
сигнатурой и докстрингом; нужно заменить `...` на реализацию. Менять
сигнатуры (имя функции, аргументы) нельзя - по ним вас проверяет
автотестирование.

В каждом файле внизу есть блок `if __name__ == "__main__":` - он уже
написан, трогать не нужно, он помогает проверить себя локально:

```bash
python task1.py
```

Данные в `data/` - пример для отладки, реальная проверка идёт на скрытых
данных и вызывает ваши функции напрямую, в том числе по отдельности - не
только через `__main__`.

## Как сдавать

Реализуйте функции в `task1.py`-`task4.py` (`task5.py` - опциональный
бонус), закоммитьте и запушьте - GitHub Actions прогонит проверку
автоматически, балл появится в summary запуска в разделе Actions.

Локально можно (и стоит) прогнать публичные тесты:

```bash
pip install -r requirements.txt
pytest public_tests/
```

**Важно:** публичные тесты - это только дымовая проверка на очевидных
случаях. Они не покрывают все ситуации, которые проверяет реальная система
оценки.

## Задание 1. Рефакторинг отчёта по кампаниям

Файл `task1.py`: `parse_campaign`, `calc_ctr`, `calc_cpc`,
`merge_duplicate_campaigns`, `format_report`.

Задача - переписать логику `messy_code.py` как отдельные функции без багов
оригинала: без целочисленного деления там, где нужно обычное, без падения
на кампаниях с нулевыми показами/кликами и с объединением кампаний, которые
экспортёр выгрузил дважды.

## Задание 2. Уникальные рекламодатели

Файл `task2.py`, функция `unique_advertisers(campaign_ids)`.

ID кампании вида `"ADV07-014"` состоит из рекламодателя и номера кампании.
Нужно получить список рекламодателей без повторов - подробности порядка в
докстринге функции.

## Задание 3. Объединение отчётов и лог предупреждений

Файл `task3.py`: `aggregate_campaigns(*reports, sort_by=..., reverse=...)` и
`log_alert(campaign_id, message, log=None, **tags)`.

Первая функция принимает произвольное число отчётов (например, за разные
дни) и объединяет их с сортировкой. Вторая - ведёт лог предупреждений и
принимает любые дополнительные теги через `**tags` (например,
`severity="high"`); внимательно прочитайте, что должно происходить, если
`log` не передан, и в каком порядке выводятся теги.

## Задание 4. Функции высшего порядка и lambda

Файл `task4.py`: `filter_and_sort(campaigns, predicate, key=None,
reverse=False)` и `ctr_desc_then_id_asc` - переменная, в которую нужно
записать `lambda`-выражение (без `def`) для сортировки кампаний по CTR.

## Критерии оценки

Каждое задание проверяется независимым набором скрытых тестов - вы не
видите ни сами тест-кейсы, ни ожидаемые значения. Итоговый балл - среднее по
заданиям: все обязательные задания весят одинаково, а внутри задания балл -
доля его пройденных тестов. Если файл задания не запускается (например, из-за
синтаксической ошибки), это задание получит 0, но остальные засчитаются. Задания не завязаны друг на друга жёстко - если одно не получилось,
переходите к следующему.
